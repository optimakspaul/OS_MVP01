# ISSUE-018 Demo Pack Notes

**Issue:** ISSUE-018
**Project:** MVP01
**Demo Route:** `/optimaks-os`

---

## 1. Demo Purpose

The demo pack gives the founder a simple walkthrough for MVP01:

```text
1. Show the end customer request preview.
2. Open the client workspace preview.
3. Walk through the Starter operation flow.
4. Show the Optimaks OS Basic tracking preview.
5. Explain what is included and what remains reserved.
```

---

## 2. Demo Story

MVP01 can be demonstrated as:

```text
End Customer Interface
-> Client Workspace
-> Lead / Customer
-> Quote Estimate
-> Booking
-> Payment
-> Reminder + Basic Report
-> Optimaks OS Basic
-> Demo / Release Pack
```

The Optimaks OS Basic page ties the demo together by showing a sample client list, plan status, onboarding status, and workspace link.

---

## 3. Demo Checklist

Use this checklist during founder review:

```text
1. Open /end-customer and explain the customer request entry point.
2. Open /workspace and explain the static Starter workflow.
3. Open /optimaks-os and explain client tracking for demo/release readiness.
4. Confirm demo content is non-persistent.
5. Confirm no real backend, billing, deployment, entitlement, or MVP02 work exists.
```

---

## 4. Demo Boundary

The demo pack is local and static.

It does not send messages, write customer records, schedule work, generate reports, process payments, create tenants, provision accounts, deploy production systems, or unlock MVP02.

---

## 5. Founder Review Note

Founder review should evaluate whether the static story is clear enough to support MVP01 final checkpoint review.

Any request to add real backend functionality, deployment automation, billing logic, entitlement logic, or MVP02 planning must become a separate approved workpack.
