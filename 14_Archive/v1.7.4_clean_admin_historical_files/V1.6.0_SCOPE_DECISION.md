# V1.6.0 Scope Decision

**Version:** v1.6.0  
**Release Name:** Plan, Template, Client Onboarding and Deployment Governance  
**Date:** 2026-05-19  
**Status:** Approved as active constitution update

---

## 1. Why v1.6.0 is needed

v1.5.9 already introduced AI Issue Execution, DONE Report requirements, and Constitution Change Control. However, the founder discussion on 2026-05-19 introduced several decisions that affect future delivery governance, not just one isolated issue.

These decisions include:

```text
- Use one stable core system instead of copying a separate codebase for every client.
- Use plan / module / template configuration to support Lite, Standard, Plus and Pro packages.
- Allow manual plan and template activation in the Optimaks admin platform first, with automation later.
- Standardize new client onboarding information before demo, production deployment or billing setup.
- Define how existing MVP-01 batch 1-18 documents should react when the constitution changes.
- Define how visual concepts, screenshots and UI sketches are converted into executable MVP 20_Issues.
```

Because these decisions affect product architecture, issue execution, client onboarding, deployment, and future industry templates, they should not remain only in chat notes.

## 4. Change Level

This release is classified as a mixed governance change:

```text
Level 2 — Process and documentation execution impact
Level 4 — Product architecture / delivery model / client deployment impact
```

Reason:

```text
- It changes how future 20_Issues should account for plan, template and client workspace behavior.
- It changes onboarding requirements before launch or deployment.
- It creates rules for how existing batch documents are reviewed when future constitution versions change.
- It does not require all existing batch 1-18 files to be rewritten immediately.
```

---

## 5. Impact on MVP-01 Batch 1-18

v1.6.0 does not require automatic full rewriting of MVP-01 batch 1-18.

Use this rule:

```text
If a batch only covers foundation setup, repo setup, base Supabase, auth, RLS, navigation, or shared UI:
    likely no immediate rewrite is required.

If a batch touches client workspace, plan tiers, admin feature toggles, template selection, deployment, onboarding, billing, demo setup, or production launch:
    add v1.6.0 supplemental notes or affected issue review.

If new functionality is required:
    create a new issue or change request instead of silently modifying completed 20_Issues.
```
